# 命令行购物助手 V1

第四周 LangChain 整合练习：让模型理解购物问题，由本地工具查询模拟单价、计算小计和合计，并保存本次运行中的对话历史。

## 项目文件

| 文件 | 职责 |
| --- | --- |
| main.py | 接收问题、管理会话编号、调用 Agent、打印回答 |
| agent.py | 创建 ChatDeepSeek，组装工具、中间件和会话保存器 |
| tools.py | 查询单价、计算小计、汇总小计 |
| middleware.py | 将工具抛出的 ValueError 转成失败消息供模型读取 |
| config.py | 从环境变量或 .env 加载配置并检查是否缺失 |
| .env | 本地 API_KEY、BASE_URL、MODEL 配置，不应公开提交 |
| requirements.txt | 当前练习使用的直接依赖版本 |

## 配置与运行

从仓库根目录进入 `week4-langchain-agent` 后执行下列命令。使用 Python 3.10 或兼容环境；当前练习使用 Python 3.10.11。

已有虚拟环境可以继续使用，无需重新安装。需要重建环境时，在项目目录中执行：

```powershell
python -m pip install -r requirements.txt
```

这里的 python 应是你要使用的虚拟环境解释器。requirements.txt 固定了直接依赖，但不是包含全部间接依赖的完整锁定文件。

在项目目录配置 .env，填入自己的真实配置：

```ini
API_KEY=你的密钥
BASE_URL=你的模型服务地址
MODEL=你的模型名称
```

当前 langchain-deepseek 1.0.1 的练习代码使用 api_base=BASE_URL，并关闭 thinking。调用模型需要网络及有效配置。

运行 main.py：

```powershell
python main.py
```

## 可以输入什么

- `三个钢笔多少钱`：查询单价并计算小计。
- `四个呢`：在同一会话中承接之前的商品信息。
- `三个笔记本加两个钢笔多少钱`：查询并计算多项商品。
- `新对话`：切换到新的 thread_id。当前输入提示未列出此命令，但代码已支持。
- `退出`：结束程序。

固定模拟单价：笔记本（纸质）12 元、钢笔 8 元、书 30 元、橡皮 1 元。不能查询实时价格或购买商品。

## 一次请求怎样执行

```text
用户输入 → main.py 提交消息及 thread_id
         → Agent 读取会话状态并调用模型
         → 模型请求工具 → 框架经过中间件执行工具
         → 工具结果回到模型 → 最终回答
```

模型也可以直接回答，无须每次调用工具。InMemorySaver 保存程序运行期间的会话状态；相同 thread_id 用于继续对话，新编号用于另一段对话。新对话不等于删除旧会话，退出进程后这份内存状态不会保留。

## 失败处理与边界

未知商品会让 get_price 抛出 ValueError，中间件捕获后返回 status="error" 的 ToolMessage。数量小于等于 0 时，calculate_total 直接返回失败字符串，不经过中间件的 except。模型服务的网络或认证错误不属于这个工具中间件的处理范围。

工具描述和系统提示词指导模型，但不能保证它始终正确选择商品、数量或工具；本项目是学习演示。

## 已观察的运行结果与待验证项

2026-11-16 用户提供日志：3 支钢笔计算为 24 元，追问 4 支计算为 32 元，随后正确复述前两个问题；两次价格回答都注明模拟数据。

| 场景 | 观察重点 |
| --- | --- |
| 三个笔记本加两个钢笔 | 两项小计 36、16，合计 52；观察是否使用汇总工具 |
| 查询书包价格 | 如实说明不支持，不改成其他商品，不编造单价 |

| 新对话后询问刚才买什么 | 不沿用此前会话的购物内容 |

运行通过与理解原理是两件事。能够说明 main、agent、tools、中间件和会话保存器分别做什么，是本阶段的学习重点。
